# 01: `--rc` compile fails ("rc check: the function of a call of a function value is not a variable or a global") when a function stored in a record field is called

Severity: high (compile error on a valid, common program; `--rc` is the default). Found by programs 14-higherorder (`runAll` calls `h.run v`) and 23-dictionaries (records of functions used as
"type class dictionaries": `m.combine a b`, `s.show x`, 9 sites). Binary `elmficA14` (also `elmficA15`). `--no-rc` compiles and runs correctly.

Minimal program (`m.fic`, in a project with the usual elm.json):

```elm
module Main exposing (main)

type alias H =
    { name : String, run : Int -> Int }

go : H -> Int -> Int
go h v =
    h.run v

main : Program () () ()
main =
    Platform.worker
        { init = \_ -> ( always () (Debug.log "r" (go { name = "a", run = \x -> x * 2 } 5)), Cmd.none )
        , update = \_ m -> ( m, Cmd.none )
        , subscriptions = \_ -> Sub.none
        }
```

Command: `elmficA14 make src/Main.fic --output=x.c --rc`

Observed: compiler exits 1, after the type check:

```
-- FICUS: the program cannot be compiled to C yet ---------------------------------
rc check: author/project:Main.go: the function of a call of a function value is not a variable or a global
-- ERROR ... I ran into something that bypassed the normal error reporting process! ... ExitFailure 1
```

Expected: C output, running prints `r: 10`, 0 live objects (Elm prints `r: 10`).

Also fails when the record is a local value (`let h = {..} in h.run 5` in `main`: `rc check: init: ...`) and with two calls
`h.run v + h.run v`. The same call through an accessor, `go h v = .run h v`, passes the rc check but is issue 02.
Workaround (checked): bind the field first, `let f = h.run in f v + f v` compiles and prints `r: 20` with 0 live objects; with that
change the rest of program 14 gives output equal to Elm's in counted + ASan mode.
